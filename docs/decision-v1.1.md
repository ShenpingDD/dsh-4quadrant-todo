## 1. 判定的标尺

三条标尺，按顺序使用：

1. PRD 有条目、实现与该条目不一致 → 缺陷。
2. PRD 有条目，但与另一条条目互相冲突，导致两条无法同时满足 → 需求变更（PRD 必须改写），不把责任归给实现。
3. PRD 没有条目 → 需求变更，先补条目再开发。

第二类与第三类的区别只在于是否需要同时改写既有条目。两类都必须改写 PRD，这是本记录与 PRD 1.1 同步发布的原因。

## 4. 版本结论

v1.1 一次交付，包含四个问题与 7 项违背项，共 11 个工作项，对应 PRD 16.4 的 T13 至 T19：

| 任务 | 覆盖项 |
| --- | --- |
| T13 角标样式随图标装载 | 问题 4 |
| T14 卡片完成与多选的动作分工 | 问题 3、D1 |
| T15 四象限方格配色 | 问题 1 |
| T16 添加面板子待办空态 | 问题 2 |
| T17 会话条目可读化与去向 | D2、D3、D4、D5 |
| T18 键盘与浮层收尾 | D6 |
| T19 固定颜色字面量清理 | D7 |

v1.1 不新增 PRD 第 3 节「本期不包含」以外的能力。这样安排的机会成本是：交付期内不扩充功能面，全部产能用于把已有条目的口径做实。这是本期的取舍，理由是当前 11 项里有 4 项（问题 4、D2、D3、D5）会让用户对入口与条目失去信任，功能面再大也无法抵消。

v1.0 的 27 条验收记录继续有效。PRD 15.1 至 15.6 的编号与文本在 v1.1 中未改动，新增条件写入第 15.7 节，编号从 28 起。
